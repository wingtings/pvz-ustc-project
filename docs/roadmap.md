## 第一优先级：收口开发试玩版

这一轮合并 v0.2、v0.3 和首批 v0.5 的必要收尾。先让现有内容能可靠交付，再扩大机制与资源范围。

R1、R2 组成下一次试玩交付，R3 作为持续回归推进。暖气片开发在 R1 和目标场景的基线验证通过后即可开始，完整发布仍须满足对应轨道的全部验收条件。

### R1：分离构建输入与运行目录

2026-09-05 的根目录 `main.pak` 已是十六项累计开发包，哈希为 `9DB70BB4…`；工具要求的干净输入为 `3B5291C6…`。这使资源测试在当前工作目录触发前置校验，干净副本的 77 项测试则全部通过。

- [ ] 增加开发运行目录的装配入口：读取匹配哈希的干净输入，把 EXE、DLL、配套资源和选定 PAK 装到独立目录，并设置正确工作目录。
- [ ] 明确文案/美术基线与临时数值测试两种组合，输出所选清单、EXE/PAK 哈希和启动说明。
- [ ] 提供基线、当前开发包、未知文件三种识别结果；保留已有开发文件，未知输入停止构建。
- [ ] 在 Git 属性中明确 PAK、EXE 等二进制文件类型，避免开发包被当作文本统计或执行空白检查。
- [ ] 整理本地 VibeGame 调研、原型、截图与证据一同入库，保留对运行产物的忽略规则。
- [ ] 拆分无需原版素材的检查，接入 GitHub Actions；依赖合法原件的完整构建和实机验证保留本地入口。

验收：新的干净工作副本能完成检查、生成 16 项资源包和运行目录；根目录基线哈希保持不变；补丁回滚输出与输入逐字节一致；开发者能明确辨认自己正在运行哪一种组合。

### R2：完成第一章连续试玩

- [ ] 用独立测试存档，从 1-1 连续完成 1-10，记录解锁、选卡、经济、出怪、胜利、失败与继续游戏。
- [ ] 检查首章出现的名称、提示和图鉴，修复乱码、截断与错误换行；把其余槽位和附加模式检查列入完整 v0.2 验收。
- [ ] 用同一累计构建完成下表中影响试玩的首批美术缺口，保留可归属到单个对象的动作证据。
- [ ] 给出完整运行目录的本地生成说明、实际测试范围和已知问题。

验收：首章可以正常连续游玩，至少完成一次失败重试及退出后继续；没有阻断进度的文字或素材问题。本轮沿用原版关序，因此通过后只记为“首章改版试玩通过”，不计作 v0.6 自定义关卡落地。

## 第二优先级：把招牌机制接入原版

三项机制按暖气片、GPA、DDL 的顺序推进。沙盘可以提前完善；原版逻辑写入以 R1 的可重建、可回滚链路及对应场景基线验证为前提。每项机制都有独立开关。

### v0.4 规则沙盘：补足边界

本地[机制沙盘](../prototypes/vibegame-mechanics-lab/README.md)已留下 2026-09-04 的首轮记录：暖气片 0.8、不叠加、寒冰 0.5 优先、保险扣 8、空投每次扣 4/最多四次。其 DDL 输入直接调用计数方法，尚未模拟真实抓取与离场；GPA 当前也只有计数显示。

- [ ] 用连续帧位移独立反算 1.0/0.8/0.5 倍率。
- [ ] 明确暖气片作用半径和跨行规则；覆盖自然进入/离开、多个暖气片、移除暖气片及寒冰结束。当前沙盘只检查横坐标距离。
- [ ] 模拟空投出现、选定目标、抓取、被击败、被弹开与携带单位离屏，加入对象标识去重。
- [ ] 覆盖暂停/恢复、重开/退出、关卡切换、分数下限、评级边界及开关组合。

验收：保存可重放的输入序列和独立观察结果；通过只代表规则可执行，不代表原版对象字段或调用时机已验证。

### v0.4 第一项：暖气片范围减速

- [ ] 定位当前 `1.0.0.1051` 的对象、行列、移动及状态更新点，记录签名、字段含义和观察证据。
- [ ] 先显示范围与受影响对象，再接入移动倍率：暖气片 80%，多个不叠加；寒冰按 50% 优先。
- [ ] 保留原版绿圈火化行为，验证暖圈清除寒冰后的状态；覆盖冻结、定身和暖气片移除。
- [ ] 在独立测试关完成开启/关闭、自然进出范围、暂停/重开与对象销毁；再做五场景抽查。

验收：录像/位移数据能证明倍率及恢复正确，关闭后回到原行为，退出关卡后无残留状态。先使用独立测试关，不提前修改战役解锁表。

### v0.4 第二项：GPA 完整度与结算

- [ ] 开局设为 100；接真实保险事件，每次扣 8，同一事件只记一次。
- [ ] 实现胜利结算 S/A/B/C，阈值与[数值规范](balance-and-levels.md)一致；补明确 GPA 为 0 时的显示约定。
- [ ] 保留原版失败判定；验证重试、存档继续、退出及机制关闭。

验收：事件、分数和评级一致，关末界面可读，GPA 不参与卡片支付，失败与重开不会沿用上一局状态。

### v0.4 第三项：DDL 空投扣分

- [ ] 接入真实空投事件链，仅在成功携带单位并离屏时扣 4。
- [ ] 被击败、被生物安全柜弹开、未抓到目标、尚未离场均不扣分。
- [ ] 用对象/事件标识防止逐帧重复结算；同关最多计四次，重开清零。

验收：成功、阻止、无目标、第五次成功和重复回调均有证据，并完成与 GPA、暖气片各自开关及组合回归。

## 第三优先级：扩大可见内容与自定义关卡

### v0.5 后续视觉

首批遗留项收口后，第二批优先选择 P23 暖气片、P06 寒冰科豆、专注值图标，以及数院草坪的选卡预览和章节标题。它们能服务第一项新机制和首章辨识度；具体资源清单先盘点再制作。

### v0.6 五章关卡重排

按[数值与关卡规范](balance-and-levels.md)把解锁、出怪和特殊关落成可审查的数据或补丁。每章先做 1 至 3 关的切片，再扩到十关。

## 当前目录与协作约定

```text
docs/               设计、技术路线、状态入口与截图
properties/         GBK 游戏文案
assets-src/          原创配方配套资料、概念稿、16 份素材契约
patches/manifests/   常量、资源与契约注册表
tools/              同步、检查、素材生成与构建工具
tests/              自动测试、手工验收记录
prototypes/         独立机制沙盘（核查时仍为本地未提交内容）
dist/               本地生成的补丁与 PAK，已忽略
.work/              原件参考、临时证据与隔离核查副本，已忽略
```

游戏文案保持 CP936/GBK，通过同步工具生成。合成 PNG、解包原件、运行日志与存档留在忽略目录中。提交时按文案、资源、常量、机制分别说明实际行为变化，并链接对应证据；完成一个可体验的里程碑后集中更新 README。
