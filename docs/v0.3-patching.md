# v0.3 可重复常量补丁

状态：补丁基础设施、静态定位和字节级回滚已完成；游戏内数值观察与跨场景回归尚未完成。

验证日期：2026-08-30

## 这一阶段解决什么

v0.3 不把临时测试数值当成正式平衡改动。它先证明四件事：

1. 只接受仓库指定的 PC 版 `1.0.0.1051`。
2. 用唯一 AOB 特征定位常量，同时检查位置上的旧字节。
3. 生成 `dist` 内的开发副本，不覆盖 `PlantsVsZombies.exe`。
4. 能从已补丁副本生成与基线逐字节相同的回滚副本。

机器可读清单位于 [`patches/manifests/v0.3-constant-proof.json`](../patches/manifests/v0.3-constant-proof.json)。

## 两处二进制定位

### P01 绿圈科豆费用

社区反编译把 `gPlantDefs` 标在虚拟地址 `0x0069F2B0`，首项 `SEED_PEASHOOTER` 的费用是 100。当前仓库 EXE 的数据表与该结构吻合：费用字段位于虚拟地址 `0x0069F2C0`、文件偏移 `0x0029F2C0`，旧字节为 `64 00 00 00`。

验证补丁把它临时改为 75，即 `4B 00 00 00`。AOB 覆盖完整的豌豆射手定义和下一项向日葵定义开头，费用四字节使用通配符，因此正向和回滚时都能定位；在基线和补丁副本中都只匹配一次。

### P04 出恭墙耐久

`PlantInitialize` 从虚拟地址 `0x0045DB60` 开始。`WALL_NUT` 分支在 `0x0045E19F` 比较种类 3，随后执行：

```text
83 F8 03                cmp eax, 3
75 09                   jne ...
C7 43 40 A0 0F 00 00    mov dword ptr [ebx+40h], 4000
```

耐久立即数位于文件偏移 `0x0005E1A7`。验证补丁把 `A0 0F 00 00` 临时改成 4200 的 `68 10 00 00`。特征同时包含后续特殊坚果分支，避免误改同一函数里的其他 4000。

这两处位置先参考了 [PlantsVsZombies-decompilation 的 `Plant.cpp`](https://github.com/ruslan831/PlantsVsZombies-decompilation/blob/master/Lawn/Plant.cpp)，最终仍以当前 EXE 的反汇编、哈希、唯一匹配和旧字节为准。

## DDL 空投图鉴

Z21 的 450 耐久已经随 v0.2 文案同步进入 `BUNGEE_ZOMBIE_DESCRIPTION`。v0.3 清单把它写成 CP936 文案断言：补丁预演、应用和回滚都会确认该节包含 `耐久：{STAT}450`，但不会重复修改 `LawnStrings.txt`。

## 使用方法

只检查，不写文件：

```powershell
python tools/apply_binary_patches.py --check
```

生成临时数值副本：

```powershell
python tools/apply_binary_patches.py --apply
```

从临时副本生成回滚副本：

```powershell
python tools/apply_binary_patches.py --reverse
```

运行自动测试：

```powershell
python -m unittest discover -s tests -p "test_binary_patches.py" -v
```

默认输出：

| 文件 | SHA-256 |
| --- | --- |
| 原版基线 | `6F1729369AC9C5F859E8F3B55FE7D513FBC20B5C54127FD3A1C7E500237FDE6F` |
| v0.3 临时补丁副本 | `CB0E0FFF4A530164582E3E0A86FA046A5217AC4293F961A75FB3097C853899B8` |
| 回滚副本 | `6F1729369AC9C5F859E8F3B55FE7D513FBC20B5C54127FD3A1C7E500237FDE6F` |

`dist` 被 Git 忽略。工具拒绝把输出写到 `dist` 以外，也拒绝输入和输出是同一路径。若目标已存在且哈希一致，它只做验证；内容不同时默认停止，只有显式给出 `--force` 才会替换开发输出。

## 当前边界

- 100→75 和 4000→4200 只是验证补丁，不是最终平衡决定。
- 当前只证明了 AOB、旧字节、输出哈希、输出隔离和回滚闭环。
- 尚未在选卡界面观察 75，也未通过实战或内存观察确认新放置的出恭墙为 4200。
- 白天、夜晚、水池、雾夜、屋顶和三个小游戏的补丁副本回归仍待执行。
- 当前仓库基线本身的 Authenticode 状态已是 `HashMismatch`，补丁工具没有把这一状态算作新增回归；公开发行前仍须改用用户自备合法原版和差分补丁。
